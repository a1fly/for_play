# 论文 AI 率降低工具 — 设计文档

**日期**：2026-05-11
**项目代号**：`ai-rate-reducer`
**目标**：本地 Web 工具，用户拖入 `.docx` 论文，自动降低 AI 检测率，**完整保留原格式**，输出新 `.docx` 文件。

---

## 1. 需求与范围

### 1.1 用户场景

用户写完毕业论文后，担心论文被知网 AIGC、Turnitin AI、GPTZero 等检测器判为 AI 生成。需要一个工具自动改写正文，使其更像人类自然写作，同时**论文的所有格式（样式、字体、字号、目录、页眉页脚、图表、公式等）必须完全保留**。

### 1.2 核心约束

- **输入**：`.docx` 文件。用户从 `.doc` 手动另存为 `.docx`（不在本工具范围内做 .doc 转换）。
- **输出**：`{原文件名}_改写版_{时间戳}.docx`，**绝不覆盖原文件**。
- **格式保护**：只修改 `run.text`，不动任何样式属性。
- **改写引擎**：通义千问 `qwen-plus` API。
- **改写粒度**：按段落，每段独立调用。
- **部署**：本地运行，`python app.py` 启动后浏览器打开 `http://localhost:5000`。
- **交互**：一键改写，下载新文件 + 改写报告。

### 1.3 不在范围内

- `.doc` 二进制格式直接处理（用户手动转）
- 公网部署、用户系统、历史记录
- 多人协作
- 桌面应用打包

## 2. 系统架构

### 2.1 技术栈

| 层 | 选型 | 理由 |
|---|---|---|
| 后端框架 | Flask | 轻量，单文件就能跑 |
| docx 解析 | `python-docx` | 成熟，能精细控制 run 级文本 |
| Qwen SDK | `dashscope` | 通义官方 SDK |
| 前端 | 原生 HTML + JS | 不引入框架，零构建 |
| 实时进度 | Server-Sent Events | 比 WebSocket 简单 |
| Python 版本 | 3.10+ | |

### 2.2 工作流程

```
用户在浏览器拖入 .docx
   ↓
POST /api/upload → 返回 task_id
   ↓
GET /api/process/<task_id> (SSE 流)
   ├─ python-docx 解析文档
   ├─ 遍历 body 段落
   ├─ 段落分类（改写 / 跳过）
   ├─ 改写段落 → Qwen API（并发 5）→ 校验 → 回写或回退
   └─ 推送进度事件
   ↓
处理完成，前端拿下载 URL + 改写报告
   ↓
GET /api/download/<task_id> 下载 docx
```

## 3. 段落分类规则

每个段落进入流程后按顺序判断。**只要命中任一"跳过"条件就跳过，全部不命中才送 AI 改写**。

### 3.1 跳过规则（按优先级）

**规则 1：标题样式跳过**
段落 `style.name` 命中以下任一关键词（不区分大小写）→ 跳过：
`Heading`, `Title`, `TOC`, `标题`, `目录`

**规则 2：特殊段落样式跳过**
样式名命中 → 跳过：
`Caption`, `题注`, `Bibliography`, `参考文献`, `Quote`, `引文`

**规则 3：段首特征跳过**（正则匹配段落前 20 个字符）

| 正则 | 含义 |
|---|---|
| `^图\s*\d+` | 图题注 |
| `^表\s*\d+` | 表题注 |
| `^Figure\s*\d+` | 英文图题注 |
| `^Table\s*\d+` | 英文表题注 |
| `^\[\d+\]` | 参考文献条目 |
| `^\d+[\.、]\s` 且在"参考文献"标题后 | 编号参考文献 |
| `^[（\(]?\d+[）\)]` 且段落 < 30 字 | 编号项 |

**规则 4：参考文献区跳过**
扫描到样式为标题且文本包含 `参考文献` / `References` / `Bibliography` 的段落后，**之后所有段落直到文档结束都跳过**（论文参考文献一般在最后一节）。

**规则 5：公式 / 代码跳过**
- 段落 XML 字符串含 `<m:oMath` 或 `<w:object` 子串 → 跳过（通过 `paragraph._element.xml` 检查）
- 段落样式名包含 `code` / `代码` → 跳过
- 段落中文字符占比 < 20% → 跳过（覆盖代码、公式残文、变量列表）

**规则 6：表格内段落跳过**
python-docx 的 `document.paragraphs` 默认**不含**表格内段落。实现时只遍历 `document.paragraphs`，天然不会处理到表格中的段落。

**规则 7：脚注 / 尾注 / 页眉页脚跳过**
python-docx 默认只遍历 `body` 段落，脚注 / 尾注 / 页眉 / 页脚天然不会被处理。**实现时不主动遍历这些区域**。

**规则 8：混合格式段落跳过**
段落 `runs` 数 ≥ 2 时，检查所有 run 的关键格式属性是否完全一致：
`bold`, `italic`, `underline`, `font.name`, `font.size`, `font.color.rgb`

任一属性在不同 run 上不一致 → 跳过。

**规则 9：太短 / 无中文跳过**
- 段落文本去空白后长度 < 15 → 跳过
- 段落不含任何中文字符（`[一-鿿]`）→ 跳过

### 3.2 改写规则

通过以上全部检查 → 送 Qwen 改写。

### 3.3 改写报告

处理完成后生成报告：
- 总段落数
- 已改写段数
- 跳过段数（分类统计：标题 N · 参考文献 N · 图表题注 N · 公式 N · 表格 N · 混合格式 N · 太短 N）
- API 失败回退段数（连同段号和原因）

## 4. Qwen 改写调用

### 4.1 API 配置

| 项 | 值 |
|---|---|
| 模型 | `qwen-plus` |
| temperature | 0.9 |
| top_p | 0.95 |
| API Key 来源 | 环境变量 `DASHSCOPE_API_KEY`，不写代码、不传前端 |
| 并发 | `concurrent.futures.ThreadPoolExecutor(max_workers=5)` |
| 单段超时 | 30 秒 |
| 重试 | 3 次，指数退避（1s, 3s, 9s） |
| 限流处理 | HTTP 429 时降并发到 1，全部处理完后恢复 |

### 4.2 Prompt 设计

#### System Prompt

```
你是一位中文学术论文润色专家，专门帮助学生把疑似 AI 生成的段落改写得更像人类自然写作，以通过 AI 内容检测（知网 AIGC、Turnitin AI、GPTZero 等）。

【AI 检测的工作原理】
检测器主要看两个信号：困惑度（用词是否过于可预测）和突发性（句子长度是否过于均匀）。AI 文本的词选择"太标准"、句长"太平均"。你的任务是把这两个特征反过来。

【必须执行的改写操作】

1. 制造句长方差（最重要）：
   - 故意打乱句子长度。一段里要有短句（3-10 字）和长句（25 字以上）穿插。
   - 不要让相邻句子字数接近。
   - 可以把一个长句拆成"主句。一个短补充。"的结构。

2. 替换高频 AI 套话（强制）：
   下列词或句式如果出现，必须换掉：
   - "综上所述"、"由此可见"、"显而易见"、"不难发现"、"值得注意的是"（这条偶尔用一次可以）
   - "首先…其次…最后"、"一方面…另一方面"（这两个结构整段最多用一次）
   - "在…的背景下"、"随着…的发展"、"具有重要意义"、"做出了巨大贡献"
   - "本文"重复出现 → 换成"该研究"、"此处"、"以下"等变体
   - "通过…可以…"、"基于…进行…"等模板化连接

3. 用词降可预测性：
   - 把过于书面、过于"安全"的词换成同义但更具体的词。
   - 例："进行研究" → "考察"/"分析"/"梳理"；"得到结果" → "获得"/"得出"/"测出"。
   - 避免"非常"、"十分"、"较为"这种语义稀薄的程度副词，要么删，要么换成更具体的程度词。

4. 增加人类痕迹（适度）：
   - 偶尔出现轻度主观表达："笔者认为"、"在一定程度上"、"似乎"、"或可"（整段最多 1 处）。
   - 偶尔的轻度冗余或补充语气，比如句尾用"——这一点尤其关键"这类破折号补充。
   - 偶尔使用反问、设问句式（整段最多 1 处）。

5. 标点规范：
   - 英文半角标点（,.;:?!）一律改为中文全角（，。；：？！）。
   - 数字与中文之间不留空格。

【必须保持不变】
- 原意、所有专业术语、学科表述
- 所有数字、数据、人名、地名、专有名词
- 引用编号如 [1][2]、(2023)，数量和位置都不能变
- 段落整体长度浮动不超过 ±20%

【禁止】
- 不要加任何解释、前缀、后缀。
- 不要用"以下是改写后的内容："这种开场白。
- 不要使用 markdown 标记（**、#、- 等）。
- 不要使用"嗯"、"啊"、"呢"等口语助词。
- 不要新增任何事实信息。
- 输出必须是纯段落正文。

【输出格式】
直接输出改写后的段落，仅此一段，没有任何其他字符。
```

#### User Prompt

```
请按上述规则改写下面这段文字。直接输出改写结果：

{原段落文本}
```

### 4.3 改写后校验（回退规则）

每段返回后做以下检查。**任一不通过 → 回退到原文**，并在报告中记录：

1. 返回为空、纯空白
2. 长度变化超过 ±40%
3. 中文字符比例骤降（原文中文占比 - 改写后占比 > 30%）
4. 含明显拒绝/解释词。任意开头匹配 → 回退：`抱歉`, `我无法`, `以下是`, `改写如下`, `好的`, `当然`
5. 引用编号 `[N]` 数量与原文不一致
6. 数字 token 数量减少超过 2 个（保护实验数据）

### 4.4 回写策略

通过校验的段落：
- 段落只有 1 个 run → `run.text = 改写后文本`
- 段落有多个 run 且格式完全一致（已通过规则 8 检查）→ 改写文本放进第一个 run，其余 run 的 text 置空（保留 run 对象本身，不删除 XML 节点）

### 4.5 费用估算

中篇本科论文约 1.5 万字、200-400 段，过滤后约 200 段需改写。每段输入约 300 token、输出约 300 token。

`qwen-plus` 单价（2026 年参考价）：
- 输入 ¥0.0008 / 1k token
- 输出 ¥0.002 / 1k token

整篇成本约 **¥0.16**。

## 5. Web 接口

### 5.1 路由

| 方法 | 路径 | 用途 |
|---|---|---|
| GET | `/` | 返回 `index.html` |
| POST | `/api/upload` | 上传 docx，返回 `{task_id}` |
| GET | `/api/process/<task_id>` | SSE 流，推送进度事件，最后一条事件携带下载 URL + 报告 JSON |
| GET | `/api/download/<task_id>` | 下载改写后的 docx |

### 5.2 SSE 事件格式

```
event: progress
data: {"current": 47, "total": 213, "stage": "rewriting"}

event: done
data: {"download_url": "/api/download/abc123", "report": {...}}

event: error
data: {"message": "..."}
```

## 6. 错误处理

| 场景 | 处理 |
|---|---|
| 上传非 .docx | 前端 + 后端双重校验，提示"请先在 Word 里另存为 .docx" |
| 文件 > 20 MB | 拒绝，提示"文件过大" |
| `DASHSCOPE_API_KEY` 未设置 | 启动时检测，前端首次访问时弹窗提示 |
| Qwen 限流 (HTTP 429) | 自动降并发到 1，全部处理完后恢复 |
| 单段调用失败 3 次 | 该段保留原文，报告记录"段号 + 失败原因" |
| 整文件处理超 30 分钟 | 中止，返回部分结果 |
| docx 解析失败 | 返回明确错误"文件损坏或不是有效 docx" |
| 临时文件清理 | `tmp/` 目录文件 30 分钟后自动删除 |

## 7. 测试策略

### 7.1 单元测试

- `test_classifier.py`：构造 `tests/sample.docx`，包含标题、正文、参考文献、图表、表格、混合格式段落，断言每段被正确归类。
- `test_processor.py`：mock Qwen client（返回固定文本），端到端跑流程，断言：
  - 输出 docx 段数与原文一致
  - 段落样式名一致
  - 字体、字号、颜色等 run 属性一致
  - 标题、参考文献等段落文本与原文一致（未被改写）
  - 改写段落的 run 数与原文一致

### 7.2 不在测试范围

- **不调用真实 Qwen API**：避免费用和 flakiness。集成测试需要时手动跑。
- **不做检测器准确率测试**：无法稳定衡量"降 AI 率"的效果，靠 prompt 设计保证。

## 8. 安全与隐私

- 本工具仅本地运行，文件不离开用户机器（除发给 Qwen 的段落文本）。
- API key 只从环境变量读取，不写日志，不传前端。
- 临时目录 `tmp/`，处理完 30 分钟自动清理。
- 不做用户系统，不存历史记录。
- 不上传任何遥测。
